# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A native iOS audiobook player called **Prismo** (the Home Screen name, `CFBundleDisplayName` in the project's build settings; the Xcode target/scheme is still `Audiobooks`, and bundle IDs are unchanged so installs keep their data): SwiftUI app + WidgetKit extension. iOS 18+, Swift 5 language mode, no third-party dependencies. See README.md for the feature list and install steps.

## Build & run

There is no Swift Package or CLI build. It is an Xcode project.

```bash
# List schemes / build for the simulator (Xcode creates schemes automatically on first open)
xcodebuild -project AudiobookPlayer.xcodeproj -list
xcodebuild -project AudiobookPlayer.xcodeproj -scheme Audiobooks \
  -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
```

Signing settings live in `Config/Config.xcconfig` (`BUNDLE_ID_PREFIX`, `DEVELOPMENT_TEAM`). `APP_GROUP_ID` is derived from them and expanded into both Info.plists and both entitlements files. Don't hard-code bundle IDs or the app group anywhere else.

## Project structure rules

- The project uses **Xcode 16 synchronized folders** (`PBXFileSystemSynchronizedRootGroup`):
  - `App/` → app target only
  - `Widget/` → widget extension only
  - `Shared/` → **both** targets
  Adding or removing a `.swift` file in these folders needs **no** `project.pbxproj` edit. Avoid hand-editing `project.pbxproj`.
- `Config/` is not a synced folder: Info.plists and entitlements are referenced by build settings only. Don't move them into a synced folder, or they'd be copied as resources and break the build.
- The app target defines the compilation condition `MAIN_APP`. Code in `Shared/` that touches app-only types (e.g. `PlayerController`) must be wrapped in `#if MAIN_APP`.

## Architecture

- `LibraryStore` (singleton, `@MainActor`, `ObservableObject`): the list of `Book`s, persisted as JSON at `Application Support/Library/library.json`. Audio lives in `Application Support/Library/Books/<uuid>/`, with an optional `cover.jpg`.
- `BookAnalyzer`: reads duration, tags, artwork and chapters. Chapters come from AVFoundation first, then `ID3ChapterParser` for MP3 `CHAP` frames, then are normalized to cover the file end-to-end. `assemble` joins several files into one global timeline.
- `PlayerController` (singleton, `@MainActor`): owns a single `AVPlayer`. A book can span several files; **all positions are global book seconds**. `Book.location(for:)` maps a global time to `(track, local)`. Track switching happens in `setTrack`, with seeks deferred via `pendingSeek` until the item is `readyToPlay`.
  - Smart rewind: `SmartRewind.amount(pausedFor:limit:)`, applied in `play()` using `pausedAt`, which persists via `book.lastPlayed`.
  - Saves position every 5s while playing, plus on pause, seek, and when the scene goes inactive.
  - Publishes Now Playing info and handles `MPRemoteCommandCenter`. With "Use chapter context" on, the Lock Screen scrubber shows the current chapter.
  - `updateWidget(reload:)` writes a `NowPlayingSnapshot` to App Group defaults, then reloads the widget and control.
- `ChapterDetector` (App/Library): Find Chapters. (1) One sequential AVAssetReader pass per file, downmixed to 8 kHz mono float, giving a 100 ms RMS level track. An adaptive threshold (5th percentile + 30% of the gap to the 60th percentile) yields silences of 1.2s or more. (2) For the longest pauses (spaced 60s or more apart, at most 160), it reads 7s after each pause at 16 kHz and runs `SFSpeechRecognizer` on-device. `chapterTitle(from:)` accepts openings like "Chapter …", "Prologue", or "Part/Book + number". A short title read right after the number (`chapterName`: 8 words or fewer, ending with a full stop or a pause) becomes the chapter name, e.g. "Chapter 3: The Burrow". (3) Two or more spoken hits: use those. Otherwise: longest pauses spaced by `minChapterLength`. There is no Find Chapters screen: the chapter list's Find Chapters card/menu and the book's long-press menu call `ChapterScanner.find(_:)`, which runs it in the background (ahead of automatic scans, even on books that already have chapters), so the player can be closed or another book played meanwhile. Progress shows on the card and in the chapter list (`ChapterScanner.progress`, `lastOutcome`). Results go through `PlayerController.replaceChapters` (loaded book) or `LibraryStore.replaceChapters(of:onlyIfUnchaptered:)`, which keep `Book.originalChapters` for restore. Needs `NSSpeechRecognitionUsageDescription` in App-Info.plist.
- **Bare-number announcements:** some narrators say just "Seven." instead of "Chapter seven". `ChapterDetector.bareNumber(in:at:)` accepts a number said on its own: ≥1.3 s between word starts before it, then a ≥1.1 s gap or a full stop after, not after "chapter/part/book/page/number", 1–300. These `Mention`s have `isBare = true`, weigh less in `bestSequence` (0.5), and a chain made only of bare numbers needs at least 3. Titles still come out as "Chapter N". After a bare number a name is only taken if ≤6 words and followed by a pause (`chapterName(needsPauseAfter:)`), since the story often starts right away. `assemble` drops all names unless at least half the chapters have one (many books are numbers only).
- **Transcript pieces:** `SpeechTranscriber` results are split at pauses, so a bare "Seven." usually arrives as the first word of its own result. The results loop keeps the last 8 words of the previous result as context (`mentions(in:offset:from:)` judges pauses with them but takes no mentions from them). Without this, bare numbers were never detected (`bareNumber` needs the word before).
- **Quiet announcements:** some narrators read "Chapter N" much more softly than the story. The detector reads the audio itself (`LevelledAudioReader`, not `AssetInputSequenceProvider`) and evens out the volume with `SpeechLeveller` (50 ms steps toward −22 dBFS, up to 12× boost, no boost below −50 dBFS, fast down / slow up) before `SpeechAnalyzer`; the SFSpeechRecognizer path levels its chunks too. Never read `AnalyzerInput.buffer` on inputs from `AssetInputSequenceProvider`: they aren't PCM buffers and it traps.
- **Resuming scans:** `ChapterDetector.detect(resume:save:)` reports `Checkpoint`s (book position + mentions heard so far) after every transcript piece / chunk, and can start from one (8 s overlap, earlier files skipped, `LevelledAudioReader(startingAt:)`). `ChapterScanner` keeps them in memory, writes `Application Support/ChapterScanCheckpoints.json` at most every 10 s, drops them when a scan succeeds, is stopped or fails (the user wants Stop to just stop and Find Chapters to start fresh: no Resume / Start-over options in the UI), and `forget(_:)` on delete. Scans interrupted by the app closing (`stoppedBecause == nil`) resume by themselves at launch (`resumeInterrupted()` from AudiobookApp); stopped/failed ones wait for Resume (long-press menu, chapter list). "Find Chapters" always starts fresh.
- **Quick pass first (speed):** `ChapterDetector.detect` measures loudness (`loudness(of:)`, 8 kHz, vDSP, no speech recognition), picks the longest pauses (`listeningWindows`: silences ≥0.8 s grouped, about one per 90 s, each window = 2.5 s before to 8 s after, plus the first 45 s) and transcribes only those windows (`LevelledAudioReader(ranges:)` feeds them back to back and maps recognizer times to file times with `place(at:)`; first word of a window has `startsWindow` so it can't be a bare number). If the result isn't `isConvincing` (≥3 chapters, no skipped number, no chapter >3.5× the typical length), it listens to the whole book as before (`Checkpoint.fullListen`). Books under 20 min, or where windows would cover >40%, skip the quick pass.
- **Prologue / Epilogue:** spoken as a heading (`isSpokenHeading`: after a full stop or pause, capitalised, followed by a pause or full stop) they become `Mention`s with `special` set and `number` 0. They're kept out of the numbering (`deduplicated` filters them); `withSpecials` adds the last Prologue before the first chapter and the first Epilogue after the last chapter. With no numbered chapters they're still added (user's request): a Prologue in the first fifth of the book, an Epilogue in the last fifth.
- **Missed announcements (gap filling):** `fillGaps` fills a single gap (12, 14 → 13) with, first, a sound-alike said on its own (`soundAlikes`: to/too→2, for→4, won→1, ate→8, -ty↔-teen, as `isWeak` mentions that never count by themselves), else (after the whole-book listen only) the longest pause between the neighbours, each side keeping ≥1 min. Pauses come from the loudness scan (`pauses(loudness:)`), which now always runs.
- **Re-listening for missed chapters:** `relistenForMissing` takes the gaps in the numbering (and a first chapter of 2–4), transcribes only windows around the longer pauses between the neighbours (≤15 per gap), with `Listening(hints:maxGain: 24)`: the missing numbers as contextual strings (`AnalysisContext.contextualStrings[.general]` / `SFSpeechRecognitionRequest.contextualStrings`) and double the volume boost. Runs after the quick pass (before falling back to the whole book) and after the whole-book listen; `fillGaps` runs after it.
- **Scan one chapter:** in the chapter list, a chapter that may hide a missed one (`ChapterDetector.missingNumbers`: Chapter 1 followed by Chapter 3, or the last chapter) can be swiped or long-pressed to listen to all of it (`findMissing`: hints + double boost). Found numbers split the chapter (`ChapterScanner.scanChapter` / `split`); if nothing is found an alert offers to scan the whole book.
- **App theme (Settings → Appearance → App theme):** `AppSettings.playerBackground` / `PlayerBackgroundStyle`: Classic (the original prism palette; player background = cover-colour mesh) or Pink smoke. Pink smoke sets `Theme.isBlossom` (→ `Palette.blossom`: accent #C2185B, white on it ≥4.5:1; page #FFF0F5; surface #FFFAFC), forces light mode (`applyAppearance`), gives the player a pink `CoverPalette.blossom` theme and the `pinkSmoke` shader (App/Views/PlayerBackgrounds.metal; `lightness` 0.32 in the player), and pages get `ThemedPageBackground` / `PrismBackground(.plain)` = pale slow smoke (lightness 0.8 + 30% white veil, 20 fps). LibraryView's content has `.id(settings.playerBackground)` so cards redraw with the new colours.
- **Heat:** whole-book transcription flat out made an iPhone 15 Pro very hot. `ScanPacing` / `ScanPacer` (end of ChapterDetector.swift) feed audio at a capped speed by `ProcessInfo.thermalState` (nominal 20×, fair 8× real time, serious/critical: pause and wait), via `PacedAnalyzerInputs` for SpeechAnalyzer and between chunks for SFSpeechRecognizer. Scans run at `.utility` priority. Keep these when changing the detector.
- `ChapterScanBackground` (App/Library): keeps chapter scans running after the user leaves the app. iOS 26+: a `BGContinuedProcessingTask` (identifier `$(PRODUCT_BUNDLE_IDENTIFIER).findChapters.<uuid>`, permitted by the wildcard in App-Info.plist `BGTaskSchedulerPermittedIdentifiers`; registered right before submitting because wildcard handlers aren't matched reliably). It shows system progress, gets progress per 0.1% (iOS expires tasks with no progress for ~30 s), and on expiry just completes the task (the app is suspended and the scan carries on when it's opened again). Earlier iOS: `beginBackgroundTask` (~30 s). `ChapterScanner` calls `scanStarted` / `progressed` / `scanningFinished`.
- `ChapterScanner` (App/Library): runs `ChapterDetector` one book at a time: on request (`find`), and automatically on imported books with `chapterSource == .none` that are at least 2 min long. Progress shows on the library cards. Results go through `PlayerController.replaceChapters` for the loaded book, otherwise `LibraryStore.replaceChapters(of:)`. It runs silently: results just appear (no alerts); progress shows on the card. Importing is quiet too: no "Imported …" alert or blocking overlay (the + button spins while files are read in), and automatic folder syncs don't announce new books. `LibraryStore.post(_:)` (queued alerts) is only for real failures and for results the user asked for (Check Now, Sync).
- `FolderSync` (App/Library): a watched folder picked once in Files (bookmark in UserDefaults). It syncs on launch, on return to foreground, and on pull-to-refresh. A top-level audio file is one book; a subfolder of audio files is one book. Files are copied in. A book is skipped when its file names and sizes match a library book, or when its path or signature is in `folder-sync.json`, so deleted books aren't re-added. The folder is the master list: a book from it whose files are all gone from the folder is deleted from the app (`removeDeletedBooks`), only after a successful full read, counting iCloud placeholders as present, keeping partly-missing books, and never when the folder looks empty; its signature is forgotten so putting the file back re-adds it. A finished book is never dropped: its audio is removed but it stays in Finished as a record (`Book.audioRemoved`, `LibraryStore.removeAudioKeepingRecord`). Deleting a finished book in the app does the same; the record's menu has only Edit Details and Remove from Finished, and `FinishedBookView` hides Listen Again for it.
- Book details (`App/Library/BookMetadata.swift`, `MetadataEnricher.swift`, `App/Views/BookDetailsView.swift`):
  - `TitleCleaner` strips file-name noise such as track numbers, "(Unabridged)" and bitrates, and splits off "Series, Book N".
  - `MetadataLookup` searches Apple's iTunes Search API (`media=audiobook`). Each `CoverRegion` country store has its own editions/covers; the default is UK (`AppSettings.coverRegion`). Open Library is the fallback, used only when the author is already known.
  - `MetadataEnricher` runs once per book (`Book.detailsChecked`) after import and on app open. It retries when offline and never overwrites hand edits.
  - Covers are always publisher covers, never audiobook art (which often says "Narrated by …"). They come from Apple's **ebook** listings (`searchAppleEbooks`) and English Open Library print editions. `publisherCover` is used by automatic lookups; `coverOptions` feeds the picker.
  - The picker has no region UI. It keeps only the same book (`isSameBook`: exact `titleKey` plus author), and removes duplicate images, library rebinds and repeat photos of one publisher and year.
  - Descriptions are the physical book's blurb (as on Goodreads), from the Open Library work (`bookDescription`), with Markdown and source footnotes removed. If there's none, the ebook text is used, else the audiobook text; both have narration and ebook-only sentences removed (`withoutNarration`). Google Books isn't used because its keyless quota is shared and often used up. Bumping `MetadataEnricher.lookupVersion` gives already-checked books one more automatic pass.
  - `Book.coverOrigin` is "file", "publisher" or "user". Lookups replace file or audiobook art with the publisher cover, but never a cover the user chose.
  - The Library's Sync button and pull-to-refresh both call `LibraryView.syncAll`. It runs a folder sync, then `MetadataEnricher.refreshAll()`. That re-checks every book not edited by hand (`detailsEdited`), lets a confident match update genre, year, publisher, series and description, and keeps existing covers. Lookups are paced at about 0.7 s apart to stay under Apple's search rate limit.
  - Edit Details (long-press a card) saves through `LibraryStore.saveDetails`, which goes through `PlayerController.updateDetails` for the loaded book.
  - Replacing cover.jpg bumps `Book.coverVersion`, which keys `CoverCache`.
  - Covers are full resolution: Apple artwork is requested at `MetadataLookup.appleArtworkSize` (3000x3000bb, which returns the original, usually 1,400–2,400 px) and stored up to `ImageUtils.coverPixels` (3000) at JPEG 0.9. Library cards use a ~640 px copy (`CoverView` default, decoded with ImageIO); the player, Finished page and Edit Details pass `fullSize: true`. Covers fetched before lookup version 5 are re-fetched once at full size (`MetadataEnricher.fullResolutionCoversVersion`). Open Library's largest (`-L`) is only ~500 px, so Apple is preferred.
- `AppSettings`: global settings in `UserDefaults.standard` (app only). Anything the widget needs must be copied into `NowPlayingSnapshot`.
- Widget buttons use `AudioPlaybackIntent` intents from `Shared/PlaybackIntents.swift`, which iOS runs in the app process.
- Medium widget: a cover as tall as the widget, title, "Chapter N of M", progress, then previous chapter / skip back / play / skip forward / next chapter (`PreviousChapterIntent`, `NextChapterIntent`). Widgets can't animate, so the title can't scroll there; it ends in "…".
- Skip icons everywhere are `SkipGlyph` (Shared/Theme.swift): the plain `gobackward`/`goforward` circle at light weight with the seconds drawn as separate text, so the circle can grow without the number growing.

## Conventions

- **Library cards:** tap opens the book; long-press opens `BookActionsMenu` in a small `.popover` beside the card (`presentationCompactAdaptation(.popover)`), and the card stays in place (it only shrinks slightly while pressed). Not `.contextMenu` (enlarged lifted preview) and not `Menu` (the card morphs into the menu); the user wants neither. Menu items come from `actions(for:)`, also offered as VoiceOver actions. The book's details card (`BookCard`) is on the open player, not the library (user's choice).
- **Don't observe `PlayerController` in big views.** It publishes `currentTime` twice a second while playing, and an `@EnvironmentObject` redraws the whole view on every change. `LibraryView` deliberately uses `PlayerController.shared` unobserved; only small pieces observe it (`LiveBook` for each card's live position, `MiniBarSpace`). Observing it in `LibraryView` made long-press menus take seconds to open.

- SwiftUI + `ObservableObject`/`@Published` (not `@Observable`). Inject via `.environmentObject`. Sheets re-inject explicitly.
- Keep UI state in views; keep playback logic in `PlayerController`. When mutating the currently loaded book, go through `PlayerController` so its copy and the library stay in sync.
- Time formatting goes through `TimeFormat` (Shared).
- Spacing uses the 4-point scale in `Spacing` (Shared/Theme.swift: 4, 8, 12, 16, 24, 32): small steps inside a group, larger between groups, 24-point side margins, and buttons at least 44 points.
- The library has two collapsible sections (tap a heading; the chevron folds it away, remembered in `@AppStorage` `librarySectionCollapsed` / `finishedSectionCollapsed`): books in progress, then a "Finished" heading and the finished books (`Book.isFinished`; no progress bar, just the length), in the same layout. Tapping a finished book opens `FinishedBookView` (cover, details, description; Listen Again, Mark as Unfinished, Edit), not the player, so it isn't loaded and un-finished by accident. "Mark as Unfinished" / "Listen Again" move it back up.
- The library's top is `LibraryGreeting` (in the scroll content, not the navigation bar): the animated `ReactiveMascot` (58 pt, mood by time of day; tap for a face) beside a short hello: "Good morning! / Ready for a story?", "Good afternoon! / Time for a chapter?", "Good evening! / Settle in with a story.", "Hello! / Up late? One more chapter?", each with the listener's name (`@AppStorage("userName")`, default "Pooja"): "Good evening, Pooja!". It replaced the big "Library" heading (user's request). The library has no navigation bar (`.toolbar(.hidden, for: .navigationBar)`): with no buttons left it only added a gap; the greeting sits 8 pt below the status bar. Under it, a "Your books" heading (title3 bold), matching the "Finished" heading (also title3 now). List view is one card per book, 12 pt apart; tiles are 24 pt apart.
- `NowPlayingPanel` is the mini bar and the full player as one surface. The open player is laid out like YouTube Music: a full-width cover (16-point margins, 8-point corners), then the title and author left-aligned under it. Mid-drag, the cover and the title (`TravellingTitle`) travel between the two layouts. The title is tied to the cover's frame (beside it, then under it, flush with its left edge), so it never crosses it. `PlayerView` reports the title's frame inside its margins.

## Now-playing panel (mini player ⇄ full player)

`App/Views/NowPlayingPanel.swift`, modelled on YouTube Music. The player is **not** a sheet. `LibraryView` overlays `NowPlayingPanel` on its NavigationStack and reserves `NowPlayingPanel.miniBarHeight` at the bottom via `safeAreaInset`.
- One surface, driven by `progress` (0 = mini bar, 1 = full). A drag anywhere on the panel follows the finger. On release, the projected end position (so flick speed counts) springs it open or closed. Taps on the mini bar, the chevron and `AppRouter.showPlayer` (book taps, widget URL) animate it the same way, and `showPlayer` stays in sync with it.
- `PanelChoreography` is `Animatable`, so springs pass through every intermediate layout. The mini controls fade out over 0–22% and the full player fades in over 50–100%. The background goes from frosted to the cover-tinted page, the corners flatten near the top, and the library dims behind.
- One travelling artwork: drawn by the panel, interpolated from the mini thumbnail rect (24, 24, 54×54) to the full player's placeholder. `PlayerView`'s artwork is an empty `Color.clear` that reports its frame in the `PlayerView.panelSpace` coordinate space via `onArtworkFrame`. If you change the mini bar's padding or thumbnail size, update `PanelChoreography.miniArtwork`.
- Child gestures win over the panel drag, so the scrubber still scrubs and buttons still tap.
- The open/close spring is sent with a marked transaction (`Transaction.isPanelMotion`), and `PanelChoreography` strips the animation from its children for it (`.transaction { if $0.isPanelMotion { $0.animation = nil } }`). The choreography is already interpolated frame by frame; letting children animate too made text and controls lag and smear (stutter). Keep this when adding things to the panel.
- `TravellingTitle` never re-lays-out text at in-between font sizes: it draws the mini bar's labels (subheadline semibold / caption) and the player's labels (title2 bold / body) at their real sizes, scales them together with `scaleEffect`, and cross-fades. It stands in for the real labels whenever 0.002 < progress < 0.998, so the swap only happens at rest, where the two are identical. (Swapping at 3%/97% made the title jump, because the cover still had 3% of its travel left.)
- Text that moves or resizes with the panel (mini bar, travelling title, player author) uses `FadedLineText`: it fades out at the end instead of "…", which otherwise jumps a letter at a time as widths change. `MarqueeText` looks identical at rest, so they swap without a jump.
- On release, the spring starts at the finger's speed (`DragGesture` velocity, relative to the distance left) and has no bounce (`interpolatingSpring(duration: 0.42, bounce: 0, initialVelocity:)`). Starting from rest made swipe-to-close stall and then move again (a visible double animation at the bottom).

### Player colours, chips and sheets (cover-driven)
- **Chips on the player are glass** (`playerGlass(in:)` in PlayerSheets.swift: Liquid Glass on iOS 26+, `.regularMaterial` before), with `.primary` icons, so they stay readable over the moving mesh background (solid cover-tinted chips had contrast problems). This covers the option chips, the audio output chip and the close chevron (`ChipIconButton(glass: true)`). The player's **sheets stay solid** (the user doesn't want glassmorphism there).
- **Colours come from the cover.** `CoverPalette.theme(for:)` (App/Views/Design.swift) finds the cover's dominant vivid hue (a weighted hue histogram, not the muddy average) and builds a light, airy `CoverTheme` (the user dislikes muddy/dark tones): `accent` (a clear colour for the play button, progress fill, selected chips), `deep`/`mid`/`light` (the background gradient: soft pastel → near white), `chip`/`onChip` (solid chip fills and their icons) and `sheet` (sheet background). All adapt to dark mode; grey covers get a neutral slate. It's passed down as `@Environment(\.coverTheme)`. The player no longer uses the blue `Theme.accent` or the iridescent ribbon (`PearlSlider` and `IridescentBar` take a `tint`).
- **Background:** `CoverMeshBackground` (Design.swift), a 4×4 `MeshGradient` of the cover's main colours (`CoverPalette` finds up to four hues ≥30° apart; a one-colour cover gets neighbouring hues): a mix of deep and light blobs (the user asked for this) at the top, beside the cover and in the bottom corners, with the row behind the chapter and progress bar kept soft/pale so text reads. The open player keeps this light look in dark mode too (user's request): `meshColors` ignores dark mode, `PlayerView` gets `.environment(\.colorScheme, .light)` (so its text, chips and sheets are light-mode), the travelling title switches to light once the background has mostly faded in, and the status bar is hidden while the player is open in dark mode (white status text would be unreadable). Its inner points drift slowly (20–35 s cycles) unless Reduce Motion is on or "Shimmer & mascot animations" is off. Colours are in `CoverTheme.mesh`.
- **Spacing knobs:** `PlayerView.Gap` (top of App/Views/PlayerView.swift): `chapterToProgress`, `progressToControls`, `controlsToOptions`.
- **Option chips:** Speed, Bookmark, Chapters, Audio output (AirPlay), More (the sleep timer was removed at the user's request). `AudioOutputChip` (PlayerView.swift) draws a normal chip with an invisible `AVRoutePickerView` on top, and keeps its icon `.primary` like the other chips (the user wants it white in dark mode), switching the symbol to show the output (airplay.audio, airpods, headphones, car) on `AVAudioSession.routeChangeNotification`. Solid `chip` capsules, 64 × 36 pt with a 44 pt tall tap area, 12 pt apart and centred as a group. **More** opens a sheet with About This Book, Edit Details and Bookmarks (Playback Settings was removed by request; it's in the Settings tab).
- **Sheets** (App/Views/PlayerSheets.swift): `SpeedSheet`, `MoreSheet`, `BookmarkSavedSheet` all use `PlayerSheetScaffold` (small round close button, centred title, solid `theme.sheet` background; it measures its content and sets the detent to fit, so there's no empty space at the bottom) and the same `SheetButton` / `ChipIconButton` pieces. Keep any new player sheet on this scaffold. Bookmarks: a tap saves it and opens `BookmarkSavedSheet` (optional note, See Bookmarks, Done) instead of alerts.
- **Long titles scroll:** the mini bar's title (while the panel is at rest), and the player's title and chapter name use `MarqueeText` (Design.swift), which scrolls only when the text doesn't fit, pauses at the start, holds still with Reduce Motion, and only runs while the player is fully open (`PlayerView.isActive`).
- **Speed buttons:** the speed sheet's quick buttons come from `AppSettings.speedButtons` (default 1×, 1.25×, 1.5×; 1–5 picked from `speedPresets`), set in Settings → Playback Speed → Speed buttons (`SpeedButtonsSettingsView`).
- `PlayBadge` draws the play triangle with no extra offset: the SF Symbol is already optically centred (a 3.5% nudge looked off-centre).

- `ReactiveMascot` (App/Views/Design.swift): a base mood that pulls a random face when tapped, and winks when `reactTo` changes. It's used in the empty library (it was removed from the player cover at the user's request).
- Find Chapters card (chapter list) mood: idle `.curious`, finding `.listening`. The splash winks before dissolving.
- The play/pause button is `PlayBadge` (Shared/Theme.swift), a plain accent circle used by both `BadgePlayButton` and the widget.
- **Archived:** the Owl mascot and the Prism/Owl theme switcher are in `Archive/Owl/`. That folder isn't built; see its README and git commit `c47f906` to restore them.

## Visual design ("prism")

- **Settings** (`SettingsView`) is a custom ScrollView, not a Form: `SettingsSection("Title") { rows }` draws a short heading above a rounded `Theme.surface` card, with hairlines between rows (`Group(subviews:)`). Headings and row text share the same left edge (16 + 16 pt). The user wants it plain: no footers or explanations, no Widgets section. Sections: Library, Playback, Speed, Progress, Appearance, Audiobooks Folder. (Book Details → Cover store was removed by request; `AppSettings.coverRegion` keeps its saved value or the UK default.)

- **Light / dark setting:** Settings → Appearance → Theme (Automatic / Light / Dark), stored as `AppSettings.appearance` (`AppAppearance`). `applyAppearance()` sets `overrideUserInterfaceStyle` on every window (so sheets and UIKit controls follow), on launch, on becoming active and when changed (with a cross-fade). All colours are dynamic, so nothing else needs to know.

Built around the mascot (`Shared/Mascot.swift`): sky blue `#078EFB`, pearl `#EEF4F9`, blush pink `#FB07CE`, ink `#0B1530`. All colours come from `Shared/Theme.swift`; don't use raw colours.
- Semantic tokens: `Theme.accent` (blue), `Theme.blush` (pink, used sparingly), `Theme.lilac`, `Theme.background`, `Theme.surface`, `Theme.hairline`, `Theme.onAccent`. `Theme.iridescent` is the cyan → blue → lilac → pink gradient used for progress.

In sheets (Edit Details, cover search, Goals, Levels, Finished book, Settings as a sheet) the smoke is a still frame with no particles, and each registers with `ModalPresence.shared` (as does the book card), which RootView folds into `pageIsVisible`, so the tab page underneath pauses too. This was the lag while typing in Edit Details.
- **Widget play/pause is a `Toggle(isOn:intent: SetPlayingIntent())`** with custom styles (`PlayToggleStyle`, `GaugeToggleStyle`, `IconToggleStyle`), not a `Button(intent:)`: WidgetKit flips a toggle's look the moment it's tapped, so the icon doesn't wait for the app's save + timeline reload (which iOS can delay). `SetPlayingIntent` still plays when asked to pause a player that isn't playing (stale state).
- **Widget / Control Center play when the app isn't running:** `TogglePlaybackIntent` and `SetPlayingIntent` call `PlayerController.playAndWait()`, which (re)loads the last book if needed, calls `play()`, then waits (up to 10 s) until `timeControlStatus == .playing` before the intent returns. Returning right after `play()` let iOS suspend the freshly launched app while the book was still loading and seeking, so nothing played.
- **Widget Play opens the app** (user's request): when the snapshot says nothing is playing, the widgets' play controls (Home Screen badge, Lock Screen circular and rectangular) are `Button(intent: PlayInAppIntent(bookID:))` (Shared/PlaybackIntents.swift, `openAppWhenRun = true`): the app comes to the front, loads that book if needed, opens the player (`AppRouter.showPlayer`) and plays (`playAndWait`). The widget can't know whether the app is still running, so Play always opens it. While playing, the control is the background pause toggle (`SetPlayingIntent`). The Control Center control stays background-only.
- Widget toggle styles must **not** wrap their look in a `Button { configuration.isOn.toggle() }`: widgets only run intents, so a closure button does nothing (that broke play/pause). The styles draw only the look; the `Toggle` takes the tap.
- **Widget progress moves live while playing:** `NowPlayingSnapshot.scopeInterval` (the chapter's or book's real-time span at the current speed, from `updatedAt`) feeds `ProgressView(timerInterval:countsDown: false)` in the medium widget's ribbon, the Lock Screen rectangle and the circular gauge (`GaugeToggleStyle.liveInterval`). iOS animates these without timeline reloads (the per-minute timeline entries alone moved it in steps too small to see). Paused: the static ribbon / gauge at the saved spot.
- **Widget play/pause, final (17 Nov, night):** the widget's toggles (`Toggle(isOn:intent: SetPlayingIntent())`) flipped the icon but didn't reach the running app (iOS seems to run that toggle's intent outside the app process), so they're gone. Controls are plain `Button(intent:)` again via `controlButton` in NowPlayingWidget.swift: while playing, or when the app is probably running, `TogglePlaybackIntent` (runs in the app, in the background; play uses `playAndWait`); when the app is probably closed, `PlayInAppIntent` (opens the app and plays). "Probably running" = `NowPlayingSnapshot.appLikelyRunning(at:)`: not `appClosed` (set in the last snapshot saved on `willTerminate`) and either playing or saved less than 10 minutes ago (`runningWindow`). The app saves a snapshot when it goes to the background (`PlayerController.refreshWidget()` from AudiobookApp), and a paused timeline adds a second entry when the 10 minutes run out, so Play switches to opening the app. `SetPlayingIntent` remains for the Control Center control only.
